Current Truth

Facturel is a local Electron app for tracking bills and payment history with no cloud connectivity. The codebase is a single December 2025 drop of ~2,070 lines: five components (Dashboard, BillForm, BillDetails, PaymentForm, Sidebar), a BillContext, an Electron shell and a 350-line SQLite manager with bills, payments, tags and bill_tags tables. Nothing in src/ has changed since that initial commit — nine months. Every commit since is tooling or docs (Dependabot Electron bump, Claude/CI workflows, June 2026 diary, status pages and AI+PROCESS notes), and nobody has recorded running the app. The reference job is the March 2026 Chronicle Pro workflow: open the app, review active bills, click through to each payee site, pay, log date/amount/notes. Facturel doesn't do that yet, as far as anyone has checked.

What It Does

A local-only bill tracker: add payees with a due date, payment URL and notes, log each payment (amount, date, notes), and keep the full editable history. It has no cloud, no banking API and no login; everything lives in a SQLite file in the user's app-data directory. Bills recur monthly, quarterly or yearly, can carry several user-defined tags, and can be archived. The app also shows payment stats (highest/lowest/average, this year vs last) and exports to CSV. It's aimed at privacy-conscious people who use something like Chronicle Pro but want full local control, and it's packaged for Mac and Windows with Electron.

The Reference Workflow — what it needs to do

From the 2026-03-27 diary: how bills actually get paid today, in Chronicle Pro.

  1. Open app → see the list of active bills
  2. For each bill: review last payment date & amount
  3. Click through to the payee website (payment URL)
  4. Pay the bill
  5. Log the payment: date + amount + notes
  6. Repeat for every bill (e.g. Amex, CIBC)

UX target: Chronicle's visual simplicity (PRD "Product Origin"). The diary also notes a wish for credit-card transaction details, and the Feb 2026 diary has a "Monthly Money Date" idea from a Financial Freedom Checklist.

Top 5 Backlog Items — ranked by what blocks actual use

  1. Payee URL quick-launch: route payment_url through shell.openExternal so it opens the real browser. This is the core workflow step; without it the app can't replace Chronicle.
  2. Recurring due-date calculation: logging a payment should roll next_due forward so the list shows what's due soon.
  3. Payment logging that persists across restarts: confirm the PaymentForm → IPC → SQLite path works, then reload and check.
  4. Bill list sorted by due date / overdue status: the dashboard currently sorts by name (ORDER BY name) and needs due-first ordering plus an overdue flag.
  5. CSV export: verify the file writes and round-trips so data isn't trapped.
